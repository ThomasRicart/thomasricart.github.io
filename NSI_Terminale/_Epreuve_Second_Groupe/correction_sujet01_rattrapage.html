    Corrigé — Épreuve du second groupe, Sujet 01 — Session 2026

    Exercice 1 — Occurrences de caractères

    def nbr_occurrences(chaine):
    ''' Renvoie un dictionnaire des occurrences de chaque caractère de la chaîne.
    chaine : une chaîne de caractères (str)
    sortie : un dictionnaire
    '''
    dico = {}
    for caractere in chaine:
        if caractere in dico:
            dico[caractere] += 1
        else:
            dico[caractere] = 1
    return dico

assert nbr_occurrences("abracadabra") == {'a': 5, 'b': 2, 'r': 2, 'c': 1, 'd': 1}

    Remarque pédagogique : on peut aussi accepter une version utilisant dico.get(caractere, 0) + 1, ou bien collections.Counter si le programme de l'établissement l'autorise. La version ci-dessus est la plus « attendue » au bac car elle ne nécessite aucun import.

    Exercice 2 — Bases de données (LIVRES / AUTEURS)

    Question 1

    SELECT titre
FROM livres
WHERE note > 10;

    En parcourant la table LIVRES, seule la ligne Ravage (note = 11) a une note strictement supérieure à 10. Toutes les autres notes sont ≤ 10.

    → La requête affiche uniquement : Ravage

    Question 2

    SELECT nom, prenom
FROM auteurs;

    Question 3

    Il faut relier les deux tables via la clé étrangère id_auteur :

    SELECT livres.titre, livres.ann_publi
FROM livres
JOIN auteurs ON livres.id_auteur = auteurs.id
WHERE auteurs.nom = 'Hugo';

    Remarque : dans le jeu de données fourni, aucun auteur ne s'appelle « Hugo » — la requête ne renverrait donc aucune ligne si on l'exécutait réellement. Cela n'est pas gênant : la question demande d'écrire la requête, pas d'en donner le résultat. Une syntaxe équivalente avec INNER JOIN explicite ou une jointure dans la clause WHERE (FROM livres, auteurs WHERE livres.id_auteur = auteurs.id AND auteurs.nom = 'Hugo') doit être acceptée.

    Exercice 3 — Arbre binaire

    Question 1 — Taille de l'arbre

    En comptant tous les nœuds de arb0 (30, 9, 5, 2, 13, 54, 15, 5, 90, 25) :

    → Taille = 10

    Question 2 — Est-ce un arbre binaire de recherche ?

    Non. Un arbre binaire de recherche impose que, pour tout nœud, toutes les valeurs du sous-arbre gauche soient inférieures à la valeur du nœud, et toutes celles du sous-arbre droit soient supérieures.

    Ici, la racine vaut 30, mais son sous-arbre droit contient la valeur 5, qui est strictement inférieure à 30. Cela viole directement la propriété d'ABR : il suffit de ce seul contre-exemple pour justifier la réponse.

    (Remarque annexe : la valeur 5 apparaît deux fois dans l'arbre, ce qui est également incompatible avec un ABR classique construit par insertions successives, mais l'argument du sous-arbre droit suffit à lui seul.)

    Question 3 — Parcours préfixe (racine, puis gauche, puis droite)

    En parcourant récursivement en commençant par la gauche :

    → 30, 9, 2, 5, 90, 13, 25, 5, 54, 15

    Détail de la construction : - préfixe(30) = 30 + préfixe(sous-arbre gauche de 30) + préfixe(sous-arbre droit de 30) - Sous-arbre gauche (racine 9) → 9, 2, 5, 90, 13, 25 - Sous-arbre droit (racine 5) → 5, 54, 15

    Question 4 — Fonction taille_arbre

    def taille_arbre(ar):
    ''' Calcule la taille d'un arbre ar passé en paramètre '''
    if ar == []:
        return 0
    else:
        return 1 + taille_arbre(ar[1]) + taille_arbre(ar[2])
    • Le cas de base : un arbre vide ([]) a une taille de 0.
    • Le cas récursif : ar[1] correspond au SAG et ar[2] au SAD, conformément à la représentation [valeur_racine, SAG, SAD] donnée dans l'énoncé.

    Remarques générales sur le sujet

    • Bon équilibre de compétences pour un oral de rattrapage de 20 minutes : algorithmique de base (dictionnaires), bases de données relationnelles (SELECT/JOIN), structures arborescentes (récursivité, ABR).
    • Le jeu de données LIVRES/AUTEURS est cohérent de bout en bout (chaque titre correspond réellement à son auteur), ce qui est appréciable pour la clarté de l'exercice.
    • Quelques coquilles typographiques à corriger dans l'énoncé (« Azimov » → « Asimov », « l'ttribut » → « l'attribut », « requette »/« requete » → « requête »), sans incidence sur la difficulté.
