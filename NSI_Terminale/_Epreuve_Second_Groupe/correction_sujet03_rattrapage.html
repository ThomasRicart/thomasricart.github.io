    Exercice 1 — Vérifier si une liste est triée

    def est_triee(L):
    ''' Vérifie si une liste est triée par ordre croissant.
    L : liste de valeurs (list)
    Renvoie : True si la liste est triée, False sinon
    '''
    for i in range(len(L) - 1):
        if L[i] > L[i + 1]:
            return False
    return True

assert est_triee([]) == True
assert est_triee([1, 2, 3, 4, 5]) == True
assert est_triee([5, 4, 3, 2, 1]) == False

    Remarque : la liste vide et la liste à un seul élément sont bien considérées comme triées (la boucle range(len(L) - 1) ne s'exécute alors jamais, et la fonction renvoie directement True).

    Exercice 2 — Arbre binaire de recherche

    Question 1 — Insertion de 9, 17, 2 dans l'arbre initial

    Arbre de départ :

            8
       / \
      3   10
     / \    \
    1   6    14
       / \   /
      4   7 13
    • Insertion de 9 : 9 > 8 → on va à droite (10) ; 9 < 10 → on va à gauche de 10, qui est vide → 9 devient le fils gauche de 10.
    • Insertion de 17 : 17 > 8 → droite (10) ; 17 > 10 → droite (14) ; 17 > 14 → droite de 14, qui est vide → 17 devient le fils droit de 14.
    • Insertion de 2 : 2 < 8 → gauche (3) ; 2 < 3 → gauche (1) ; 2 > 1 → droite de 1, qui est vide → 2 devient le fils droit de 1.

    Arbre final :

                  8
            /   \
           3      10
         /   \       \
        1     6        14
         \   / \      /   \
          2 4   7    13   17

    Question 2 — Méthode inserer

    class Noeud:
    def __init__(self, valeur):
        self.valeur = valeur
        self.gauche = None
        self.droit = None

    def inserer(self, valeur):
        ''' Insère une nouvelle valeur dans l'arbre binaire de recherche '''
        if valeur < self.valeur:
            if self.gauche is not None:
                self.gauche.inserer(valeur)
            else:
                self.gauche = Noeud(valeur)
        else:
            if self.droit is not None:
                self.droit.inserer(valeur)
            else:
                self.droit = Noeud(valeur)

    Logique : on compare valeur à la valeur du nœud courant. - Si elle est plus petite, on descend à gauche (en créant un nouveau nœud si le sous-arbre gauche est vide, sinon on délègue récursivement à self.gauche.inserer(valeur)). - Sinon (valeur plus grande — l'énoncé garantit qu'il n'y a pas de doublons), on fait la même chose à droite.

    Question 3 — Parcours infixe (in-order) du second arbre

    Arbre concerné :

            6
      /   \
     3      8
    / \    /
   2   4  7

    Le parcours infixe visite : sous-arbre gauche, puis la racine, puis le sous-arbre droit, récursivement.

    → Ordre obtenu : 2, 3, 4, 6, 7, 8

    Remarque pédagogique : on retrouve ici la propriété fondamentale du parcours infixe d'un arbre binaire de recherche — il produit toujours les valeurs triées par ordre croissant. C'est une bonne vérification de cohérence : si le résultat n'est pas trié, soit l'arbre n'est pas un vrai ABR, soit le parcours a été mal effectué.

    Exercice 3 — Base de données « orchestre »

    Question 1 — Résultat de la requête

    SELECT Nom, Prenom FROM musiciens WHERE Code_instrument = 4;

    Les musiciens ayant Code_instrument = 4 sont Alice Dupuis et Phillipe Tourelle.

    Résultat :

    Nom Prenom
    Dupuis Alice
    Tourelle Phillipe

    Question 2 — Musiciens avec ancienneté ≥ 5 ans, triés par nom

    SELECT Nom
FROM musiciens
WHERE Anciennete >= 5
ORDER BY Nom;

    En vérifiant les données, les musiciens concernés sont Claudine Dupont (5 ans), Doume M'bake (7 ans) et Alice Dupuis (9 ans), soit, une fois triés par ordre alphabétique de nom : Dupont, Dupuis, M'bake.

    Question 3 — Nom et prénom de tous les musiciens violonistes

    Le type d'instrument (« Violon ») se trouve dans la table instruments, pas dans musiciens : il faut donc faire une jointure sur Code_instrument.

    SELECT musiciens.Nom, musiciens.Prenom
FROM musiciens
JOIN instruments ON musiciens.Code_instrument = instruments.Code_instrument
WHERE instruments.type_ins = 'Violon';

    En exécutant cette requête sur les données fournies (codes instrument 1 et 2 correspondent à « Violon »), on obtiendrait : Dupont Claudine, Descarte Hugo, Fernandez Kader, Leclerc Jean, Lefevre Marie.

    Remarques générales sur le sujet

    • C'est le sujet le mieux construit des trois vus jusqu'ici : l'exercice 2 offre une bonne progression (insertion manuelle → code orienté objet → parcours), et l'exercice 3 propose une véritable jointure exploitable avec les données fournies (contrairement au sujet 01 où l'auteur demandé n'existait pas dans la table).
    • Le parcours infixe de l'exercice 2 (question 3) donne une suite triée, ce qui est une bonne façon de vérifier la compréhension de la propriété d'un ABR plutôt qu'une simple application mécanique de l'algorithme.
    • Détail cosmétique sans impact : les adresses mail de la table musiciens sont assez hétérogènes dans leur format (prenom.nom@mail.fr vs kader454@mail.fr), et l'une d'elles (Hugo.arnaque@mail.fr) est un clin d'œil sans doute volontaire — aucune incidence sur la résolution.
